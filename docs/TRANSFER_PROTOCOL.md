# Protocole de copie directe V4

Deux transports radio sont proposés. **Bluetooth classique RFCOMM** utilise l'association Android et un UUID de service Minimal OS. **Wi-Fi Direct** découvre un appareil à proximité, négocie un groupe P2P et utilise TCP 38742 uniquement *à l'intérieur de ce groupe*. Ni l'un ni l'autre n'exige un Wi-Fi commun, un hotspot configuré, une adresse IP saisie ou Internet. Sur Wi-Fi Direct, le client du groupe lance la session vers l'adresse de son chef ; si Android donne le rôle de chef au téléphone qui a demandé la copie, il faut la lancer depuis l'autre appareil.

`core-replication` exécute le même protocole sur les flux Bluetooth et sur le socket Wi-Fi Direct : défi-réponse mutuel avec le code partagé, clé de session dérivée, AES-GCM, échange de manifestes, copie des fichiers manquants dans les deux sens par blocs de 64 Kio, reprise et reçus authentifiés après vérification de la taille et de SHA-256. Les originaux restent locaux et les suppressions ne sont jamais propagées. Les copies reçues sont dans l'espace privé de l'APK.

La planification par `JobScheduler` demande une tentative après 10/15/20/30 minutes sans exiger de réseau Android validé. Elle peut être différée. Elle tente de joindre l'appareil Bluetooth enregistré ou de redécouvrir le pair Wi-Fi Direct. Le service de réception au premier plan doit tourner sur l'autre téléphone. Aucun accusé ni message « copie vérifiée » n'est produit si la session chiffrée échoue. Bluetooth peut être très lent pour des vidéos ; il faut mesurer le débit réel.

Au milieu d'une foule dense, aucun canal Wi-Fi n'est garanti libre. Une application Android ordinaire ne peut pas imposer de manière fiable le canal ou la bande du groupe Wi-Fi Direct. Le Bluetooth partage aussi le spectre 2,4 GHz et peut être congestionné. Les deux transports offrent un choix de repli, pas une garantie de réception ou de temps de transfert. Les essais sur les appareils et lieux cibles restent nécessaires.

La V4 n'implémente ni QR d'identité, ni BLE, ni coffre chiffré indépendant de l'APK. La découverte Wi-Fi Direct révèle les appareils visibles et n'authentifie pas à elle seule un pair : seule la session avec le code partagé autorise la copie. Si Android refuse les permissions radio, coupe le service, ou change le rôle P2P, une tentative peut échouer sans perte de l'original.
